# UI-тесты загрузки материалов — tpivt6_26-46

Selenide + JUnit 5, сценарии TC-UPL-01–04. Нужны запущенные Docker frontend, backend, PostgreSQL и SeaweedFS, установленный Chrome и JDK.

## Запуск кнопкой в IDEA

1. Открой проект `C:\JavaPrj`.
2. Правой кнопкой на `ui-tests/build.gradle.kts` → **Link Gradle Project** (если модуль ещё не подключён), затем обнови Gradle.
3. Открой `MaterialUploadUiTest.java` и нажми зелёный треугольник возле нужного `@Test` → **Run**. Возле класса запускаются все четыре сценария.
4. Chrome открывается с видимым окном по умолчанию. Подготовка пользователя и предмета тоже выполняется через UI. Между сценариями браузер перезапускается, после проверки выполняется очистка материалов.

Каждый метод можно запускать отдельно: `@BeforeAll` подготавливает пользователя и предмет независимо от выбранного теста. Для пошагового наблюдения поставь breakpoint на нужной строке и выбери **Debug**, затем **Step Over**.

Настройки общие для JUnit в IDEA и Gradle. Если ChromeDriver автоматически не запускается, скопируй `ui.local.properties.example` в `ui.local.properties` и укажи свой путь к совместимому драйверу. Локальный файл игнорируется Git; у Tim он уже подготовлен. Параметры JVM `-Dui.*` имеют приоритет. При обновлении Chrome нужно проверить совместимость локального драйвера.

## Структура

- `pages/LoginPage`, `RegisterPage`, `DashboardPage`, `MaterialsPage`, `UploadPage` — страницы, используемые сценарием.
- `pages/DeleteMaterialModal` — окно подтверждения удаления тестовых материалов.
- Публичные поля содержат XPath и `@Name`, например:

```java
@Name("Название материала")
public final SelenideElement nameInput = $x("//*[@id='material-name']");
```

Тест работает с ними напрямую:

```java
uploadPage.nameInput.setValue("Загрузка материала 001");
uploadPage.submitButton.click();
uploadPage.successTitle.shouldBe(visible);
materialsPage.deleteModal.confirmButton.click();
```

`support/Name` — аннотация проекта. `NamedPage` передаёт её значение в Selenide `as()`, чтобы ошибки называли элементы по-русски. `BrowserSettings` настраивает запуск браузера. Повторяемые операции подготовки и очистки оставлены методами Page Object.

## Команды

Из корня репозитория:

```powershell
docker compose up -d
.\backend\gradlew.bat -p .\ui-tests test
```

Только успешная загрузка:

```powershell
.\backend\gradlew.bat -p .\ui-tests test --tests "*MaterialUploadUiTest.successfulUpload"
```

Каждый запуск действительно выполняет тесты, без `UP-TO-DATE`. Для запуска без окна используй `-Dui.headless=true` в VM options IDEA или `$env:GRADLE_OPTS='-Dui.headless=true'` в PowerShell. Удали ранее установленные `ui.headless` из конфигурации запуска, если хочешь использовать видимый режим по умолчанию.

Отчёт: `ui-tests/build/reports/tests/test/index.html`.

При `SessionNotCreatedException` подробный журнал запуска сохраняется в `build/reports/chromedriver.log` относительно рабочей папки теста; абсолютный путь печатается в консоли. `ui.chromeBinary` в локальном файле позволяет явно выбрать установленный Chrome вместе с `ui.chromeDriver`. Предупреждения SLF4J об отсутствии провайдера не являются причиной падения Chrome.

Файлы lecture.txt и image.png создаются автоматически. Selenide передаёт файл в `input[type=file]` через `uploadFile`, поэтому системный диалог Windows не открывается. Для TC-UPL-04 ответ только на POST `/api/materials` подменяется на 500; остальные запросы идут к реальным FE/BE. Новый пользователь изолирует каждый запуск; после него материалы удаляются, учётная запись остаётся в тестовой базе.

## Редактирование материалов — tpivt6_26-49

`MaterialEditUiTest` использует те же BrowserSettings, именованные поля Page Object и видимый Chrome. Можно запустить отдельный метод кнопкой Run в IDEA (от обычного пользователя, без прав администратора).

```powershell
.\backend\gradlew.bat -p .\ui-tests test --tests "*MaterialEditUiTest"
```

- TC-EDIT-01 `changeName`: меняется только название; остальные поля M1 и другие материалы сравниваются с исходными.
- TC-EDIT-02 `changeSubject`: меняется предмет; имя и параметры файла не меняются; форма содержит только два редактируемых поля.
- TC-EDIT-03 `rejectBlankRequiredFields`: четыре независимых параметризованных запуска — пустое и пробельное название/предмет. Проверяются ошибка, отсутствие PATCH и исходные данные после обновления страницы.
- TC-EDIT-04 `cancelEditing`: введённые значения отменяются, PATCH не отправляется, повторное открытие показывает исходные данные.
- TC-EDIT-05 `retryAfterServerError`: PATCH получает 500; форма не закрывается и сохраняет введённые значения; повторное сохранение отправляется на реальный BE и проверяется после обновления.
- TC-EDIT-06 `persistAfterRefresh`: после настоящего сохранения и обновления страницы список и окно показывают новые данные.

Всего девять запусков: пять обычных тестов и четыре варианта TC-EDIT-03. Каждый запуск через UI регистрирует нового пользователя и загружает три TXT-материала: «Алгебра» и «Геометрия» в «Математика», «Лекция по SQL» в «Базы данных». Последние два — контрольные материалы; они не должны измениться. В конце материалы удаляются. Учётные записи остаются в тестовой БД. Подготовка и очистка также видны в браузере.

В текущем UI редактирование предмета реализовано текстовым полем, поэтому тест вводит «Базы данных», а не выбирает пункт выпадающего списка. `EditMaterialModal` содержит поля окна; `MaterialRow` — элементы отдельной строки и снимок отображаемых данных (название, предмет, формат, размер, дата).

## Удаление материалов — tpivt6_26-48

`MaterialDeleteUiTest` содержит TC-DEL-01–05. Запускается кнопкой Run возле класса или отдельного метода в IDEA; браузер видимый. IDEA нужно запускать без прав администратора.

```powershell
.\backend\gradlew.bat -p .\ui-tests test --tests "*MaterialDeleteUiTest"
```

Каждый тест через UI регистрирует отдельного пользователя и загружает M1 «Алгебра», M2 «Геометрия», M3 «Тригонометрия» с предметом «Математика». После теста оставшиеся материалы удаляются; пользователь остаётся в тестовой БД. Запуски независимы и не требуют ручной подготовки.

- `confirmationDialog`: окно указывает M1, показывает предупреждение и кнопки; до подтверждения список не меняется, DELETE не отправляется.
- `successfulDelete`: реальный BE удаляет M1; счётчик равен 2, M2 и M3 полностью сохранены.
- `cancelDelete`: отмена закрывает окно без DELETE, список и счётчик остаются прежними, в том числе после обновления страницы.
- `serverError`: DELETE получает 500 без удаления; UI сообщает об ошибке и нуле удалённых материалов; все три строки сохраняются после обновления.
- `deletionPersistsAfterRefresh`: реальное удаление M1 не отменяется обновлением страницы.

Используются общие `DeleteMaterialModal`, `MaterialRow` и `MaterialsPage` с публичными именованными элементами. Сравниваются не только названия оставшихся строк, но и предмет, формат, размер и дата. В проверках отсутствия DELETE перехватчик подсчитывает запросы и блокирует случайное удаление; успешные сценарии используют реальный backend и хранилище.

## Просмотр списка — tpivt6_26-47

`MaterialListUiTest` содержит пять независимых сценариев TC-VIEW-01–05. Запуск — кнопка Run возле метода/класса в IDEA (без прав администратора), Chrome видимый:

```powershell
.\backend\gradlew.bat -p .\ui-tests test --tests "*MaterialListUiTest"
```

| Материал | Владелец | Предмет | Файл | Отображение размера |
| --- | --- | --- | --- | --- |
| M1 «Алгебра» | A | Математика | algebra.pdf | Б |
| M2 «Базы данных» | A | Базы данных | databases.docx | КБ |
| M3 «Введение в SQL» | A | Базы данных | sql.txt, 1 048 576 байт | 1 МБ |
| M4 «Физика» | B | Физика | sql.txt | 1 МБ |

`MaterialListFiles` создаёт настоящие PDF, DOCX (OOXML ZIP) и UTF-8 TXT без дополнительных библиотек. Ожидаемый размер рассчитывается из числа байт подготовленного файла, а дата сравнивается с UTC-датой до/после отправки загрузки, включая случай смены даты. Значения не копируются из проверяемого интерфейса.

- `listSeveralMaterials`: три точных названия без дублей, пустой поиск/фильтр, счётчик 3.
- `emptyList`: реальный новый пользователь без материалов, пустое состояние без ошибки, счётчик 0 и переход к загрузке.
- `retryAfterListError`: только GET `/api/materials` получает 500; ошибка не показывается как пустой список. После снятия перехвата кнопка «Повторить» загружает реальные M1–M3.
- `showCorrectMetadata`: названия, предметы, PDF/DOCX/TXT, цветовые классы индикаторов, размеры в Б/КБ/МБ и даты ДД.ММ.ГГГГ. В текущем дизайне иконкой формата служит стилизованный бейдж с аббревиатурой.
- `isolateUsersAfterLogout`: в одном браузере A выходит через UI, B входит; каждый видит только собственные материалы, в том числе после обновления. Выход также проверяет очистку сохранённой сессии.

Каждый тест регистрирует отдельного пользователя A; B создаётся только для проверки доступа. Материалы создаются через UI только там, где нужны. Очистка удаляет материалы всех созданных пользователей, временные файлы и закрывает браузер; тестовые учётные записи остаются в БД.
