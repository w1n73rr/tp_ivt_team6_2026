# Браузерные проверки страницы «Тесты» — tpivt6_26-81

В модуле `tests/ui` используются Selenide и JUnit. Проверки завершаются появлением сохранённого теста в таблице. Кнопка прохождения проверяется как заглушка TY5.

## Отдельный стенд

Нужны Docker Desktop с Linux-контейнерами, Chrome и JDK 21 для UI. Для запуска контролируемого Backend нужен JDK 25. Выполняйте команды из корня проекта.

1. Создайте локальный `.env.generation.local` из `.env.example`, если файла ещё нет. Заполните четыре секрета, как описано в корневом README. Для отдельного стенда задайте `FRONTEND_PORT=13001`, `BACKEND_PORT=18081`, `POSTGRES_PORT=15433`, `S3_PORT=18333`. Если порты заняты, выберите свободные и укажите соответствующий адрес в настройках UI. Ключ OpenRouter для этого прогона не требуется.
2. Поднимите стенд. Compose создаст отдельную БД и хранилище для проекта `generation-acceptance`.

   ```powershell
   docker compose -p generation-acceptance --env-file .env.generation.local up -d --build --wait
   ```

3. Скопируйте `tests/ui/ui.local.properties.example` в `tests/ui/ui.local.properties`, если файла ещё нет. Добавьте `ui.baseUrl=http://localhost:13001` или адрес из шага 1. Каждый сценарий регистрирует нового тестового пользователя. Используйте локальный тестовый стенд.
4. Для проверки сохранения запустите контролируемое окружение задачи 68. Сервер использует отдельную БД `generation_ui_controlled` и отдельный бакет. Команда запуска сервера остаётся активной в отдельном окне PowerShell с JDK 25.

   ```powershell
   .\deploy\scripts\start-generation-ui-test-frontend.ps1
   .\deploy\scripts\start-generation-ui-test-server.ps1
   ```

Подробнее об окружении и тегах в [инструкции генерации](../generation/README.md).

## Запуск кнопкой в IntelliJ IDEA

Подключите `tests/ui/build.gradle.kts` как Gradle-проект и выберите JDK 21 для Gradle и модуля. Откройте `QuizListUiTest.java` и нажмите зелёный треугольник рядом с классом или отдельным методом. Для проверки сохранения нажмите треугольник рядом с методом `renameAndDeletePersistedQuiz` в `QuizGenerationUiTest.java`.

Те же проверки из PowerShell с JDK 21:

```powershell
.\tests\ui\gradlew.bat -p .\tests\ui test --tests "*QuizListUiTest" --tests "*QuizGenerationUiTest.renameAndDeletePersistedQuiz"
```

HTML-отчёт находится в `tests/ui/build/reports/tests/test/index.html`, XML для CI — в `tests/ui/build/test-results/test/`. Сведения о тестовой среде и коммите следует приложить к результату прогона. Существующее задание UI в CI обнаруживает класс автоматически и исключает тег `live-ml`.

## Покрытие и границы подмены

| Проверка | Окружение |
| --- | --- |
| TC-TESTS-01/02: таблица и поля, загрузка, пустой список, 401, 500 и повтор | Настоящий браузер и приложение, подменён только GET списка |
| TC-TESTS-03/04: поиск, очистка, сортировка по названию, материалу и дате в обе стороны | Ответ GET содержит три независимые строки |
| TC-TESTS-05/06/08: отмена без PATCH/DELETE, запрет пустого названия | Подменены ответы API тестов, контролируется число запросов записи |
| TC-TESTS-07/08: серверные ошибки переименования и удаления | Подменены ответы записи, проверяются диалог, сообщение и сохранение строки в UI |
| TC-TESTS-09/10: переход в материалы, заглушка прохождения | Настоящий интерфейс с тестовым списком |
| Результат генерации, переименование и удаление после перезагрузки | Настоящие FE, HTTP API, Backend и БД. Подменена внешняя ML-модель |

Набор содержит 26 вариантов с контролируемыми HTTP-ответами и одну проверку сохранения через реальный Backend. Проверка настоящей внешней модели остаётся в сценарии `generateAndPersistRealQuiz` задачи 68 и запускается отдельно. Подменённый GET не подтверждает серверную фильтрацию по владельцу. Не автоматизированы все границы длины и регистра названий, отдельный обрыв сети и сортировка при равных ключах.

Новых переменных окружения нет. Настройки стенда описаны в существующем `.env.example`, настройки браузера — в `ui.local.properties.example`. Реальные секреты остаются в локальных файлах.
