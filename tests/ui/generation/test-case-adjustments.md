# Что изменить в описании кейсов после автоматизации

Уточнения согласованы пользователем в чате: расхождения разрешено привести
к реализованному UI. Это предложения для командного документа, не изменение
карточки Сферы и не отдельное согласование PO.

1. **TC-GEN-02/03 — тип:** радиогруппа, ровно один выбранный тип. Его нельзя
   выключить повторным нажатием. Проверять по очереди все три типа. Defaults
   сравнивать с серверным справочником, а не ожидать «все три типа включены».
2. **TC-GEN-04 — статусы:** использовать фактические QUEUED/RUNNING и этапы
   PREPARING/GENERATING/VALIDATING/SAVING; только COMPLETED с quizId — готовность.
3. **TC-GEN-05 — переход:** после подтверждения сохранения показывается «Тест
   готов». «К готовому тесту» ведёт к таблице тестов; проверяются строка и
   сохранение после refresh. Автоматического открытия первого вопроса нет.
   Прохождение и оценивание в этот набор не включены.
4. **TC-GEN-06:** исключить сценарий «7 из 10» из текущего набора. Backend
   требует точное количество. Автотест не объявляет частичный ответ успешным.
5. **TC-GEN-08 — отказ запроса повтора:** пользователь видит ошибку на форме
   настроек, значения сохранены, кнопка запуска доступна. Терминальная ошибка
   уже принятой задачи остаётся отдельным экраном с «Повторить генерацию».
6. **TC-GEN-09 — ожидание:** изменять настройки до завершения нельзя, кнопки
   «К настройкам» в ожидании нет. Можно уйти через «Мои материалы»; задача не
   отменяется, её завершение не перенаправляет с другой страницы. Возврат
   к сохранённым настройкам проверяется с экрана терминальной ошибки.
7. **TC-GEN-12 — запуск не принят:** HTTP 500/сетевой сбой показываются на
   форме как «Не удалось запустить генерацию». Имя, количество, сложность и
   тип сохраняются. Экран ожидания и готовый тест не появляются; счётчики
   задач/сохранённых тестов и вызовов ML не меняются в воспроизводимом сбое.
8. **Данные:** для автоматизации используются корректные PDF/DOCX/TXT с
   учебными фактами о тестировании ПО, уникальные названия и новые аккаунты.
   Исходные «Алгебра»/«Базы данных»/«SQL» — примеры, не обязательные имена.

Не смешивать режимы: controlled — настоящий backend/БД/S3 с управляемым ML;
live-ml — настоящий внешний провайдер. Успех controlled не подтверждает
качество модели или успешное прохождение live-ml.
