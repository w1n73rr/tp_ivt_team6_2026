# Тест-кейсы генерации теста

Основа: предоставленные TC-GEN-01–12, `backend/GENERATION.md`,
`backend/TESTING.md` и контракт dev `e5f98eb`.
Уточнение пользователя: за запуск выбирается **ровно один** тип вопросов.
Прохождение и оценивание теста не входят в проверки.

## Данные и окружение

Настоящие backend, PostgreSQL и S3; отдельные пользователи A и B.
M1 — algebra.pdf, «Алгебра»; M2 — databases.docx, «Базы данных»;
M3 — sql.txt, «Введение в SQL»; все принадлежат A. M4 принадлежит B.
Документы содержат достаточный учебный текст: PDF с текстовым слоем, не скан;
DOCX без защиты; TXT в UTF-8. До 10 МБ, PDF до 10 страниц,
извлечённый текст до 30 000 символов. Имя теста уникально для прогона.
Для локального smoke допускается `backend/src/test/resources/ml/demo-lecture.txt`;
это замена материала, а не доказательство прохождения всех трёх форматов.

Параметры: 5/10; EASY/MEDIUM/HARD; SINGLE_CHOICE/MULTIPLE_CHOICE/TRUE_FALSE.
Defaults проверяются по `GET /api/generation/parameters`, без фиксации
демонстрационных значений frontend. JWT получают через регистрацию/вход;
ключ провайдера существует только в серверном окружении.

## TC-GEN-01: Открытие настройки выбранного материала (позитивный, UI)

**Предусловия:** A авторизован, открыт список с M1.

| № | Шаг | Ожидаемый результат |
|---|---|---|
| 1 | Нажать «Создать тест» у M1. | Открыта настройка именно M1. |
| 2 | Проверить карточку и форму. | Название, формат и размер правильные; нет даты, числа страниц, статуса ИИ, смены материала, тем и открытых вопросов. |
| 3 | Нажать «Назад к материалам». | Открыт список материалов. |

## TC-GEN-02: Настройки и сводка (позитивный, UI + API справочника)

**Предусловия:** новая форма M1; доступен серверный справочник параметров.

| № | Шаг | Ожидаемый результат |
|---|---|---|
| 1 | Получить справочник и открыть форму. | Defaults формы совпадают с defaults API; выбран один тип. |
| 2 | Последовательно выбрать 5 и 10 вопросов, каждую сложность. | Доступны только разрешённые значения; сводка соответствует выбору. |
| 3 | Последовательно выбрать каждый из трёх типов. | Новый выбор заменяет предыдущий; одновременно выбран ровно один тип. |
| 4 | Проверить сводку. | Показаны текущие параметры и «Тест будет составлен по выбранной лекции». |

## TC-GEN-03: Отсутствующий тип (негативный, UI/API)

**Предусловия:** валидные M1, количество и сложность; включён перехват запросов запуска.

| № | Шаг | Ожидаемый результат |
|---|---|---|
| 1 | Проверить возможность снять выбор типа. | Если используется обязательная радиогруппа, UI не позволяет оставить её пустой. |
| 2 | Если пустое состояние доступно, попытаться запустить генерацию. | Видна валидация; POST запуска не отправлен. |
| 3 | Через API отправить запрос без questionType. | HTTP 400; задача и тест не создаются. |

Несколько типов в одном запросе не являются позитивным сценарием.

## TC-GEN-04: Запуск и ожидание (позитивный, мок API)

**Данные:** независимо M1/5/EASY/SINGLE_CHOICE,
M2/10/MEDIUM/MULTIPLE_CHOICE, M3/5/HARD/TRUE_FALSE.
Мок возвращает 202 с jobId, далее QUEUED и RUNNING.

| № | Шаг | Ожидаемый результат |
|---|---|---|
| 1 | Выбрать настройки варианта и запустить. | POST /api/quizzes содержит materialId, questionCount, difficulty, один questionType и Idempotency-Key. |
| 2 | Дождаться 202. | Экран ожидания относится к принятой задаче; 202 не представлен как готовый тест. |
| 3 | Получить несколько обновлений статуса. | Отслеживается тот же jobId; параметры не меняются, интерфейс остаётся в ожидании. |

## TC-GEN-05: Успешная генерация и сохранение (позитивный)

**Предусловия:** настоящие BE/БД/S3; отдельно управляемый ML и обязательный настоящий ML.
**Варианты:** M1/5/EASY/SINGLE_CHOICE; M2/10/MEDIUM/MULTIPLE_CHOICE;
M3/5/HARD/TRUE_FALSE. Каждый запуск независимый.

| № | Шаг | Ожидаемый результат |
|---|---|---|
| 1 | Запустить генерацию с новым Idempotency-Key. | HTTP 202, jobId и корректный Location. |
| 2 | Получать GET /api/generation-jobs/{jobId}. | Допустимые статусы QUEUED/RUNNING, затем COMPLETED с непустым quizId; версии не уменьшаются. |
| 3 | Дважды прочитать GET /api/quizzes, обновить страницу списка. | Ровно одна запись с quizId, правильным материалом, количеством, сложностью и типом; запись сохраняется после повторного чтения. |
| 4 | Повторить исходный POST с тем же ключом и телом. | Возвращён тот же jobId, второй тест не создан. Другие параметры с тем же ключом дают 409. |
| 5 | Прочитать собственный сохранённый результат в БД тестового стенда. | Количество вопросов соответствует данным; все вопросы выбранного типа, уникальные ID и тексты; нет смысловых дублей. SINGLE_CHOICE: 4 варианта/1 правильный; MULTIPLE_CHOICE: 4/2–3; TRUE_FALSE: 2/1. |
| 6 | Оценить каждый вопрос, ответы и объяснение по источнику. | Нет противоречий материалу и неоднозначных ключей; EASY — воспроизведение, MEDIUM — различение/применение, HARD — совместное применение правил. Вердикт с примерами записан отдельно от технического PASS. |
| 7 | Проверить переход UI при реальном COMPLETED. | Состояние готовности привязано к quizId. Переход к первому вопросу из исходного документа требует согласования с текущим решением о таблице тестов. Демонстрационный экран не считается интеграцией. |

Минимум один вариант обязан пройти с настоящим ML. Моки не подтверждают
качество модели; один успешный TXT не подтверждает PDF/DOCX и все сложности.

## TC-GEN-06: Частичный результат (настоящий BE + мок ML)

**Данные:** запрос 10/MEDIUM/SINGLE_CHOICE; ML возвращает 7 пригодных вопросов.

| № | Шаг | Ожидаемый результат |
|---|---|---|
| 1 | Запустить и дождаться терминального состояния. | Зафиксированы фактический статус и количество сохранённых вопросов. |
| 2 | Сверить поддержку частичного результата с согласованным контрактом. | Исходный документ требует 7 вопросов и предупреждение «Создано 7 из 10 запрошенных вопросов». Если backend требует точное количество, кейс заблокирован до решения PO; FAILED не выдаётся за выполнение исходного требования. |

## TC-GEN-07: Терминальные ошибки (негативный, BE + управляемые моки)

**Варианты, независимо:** ошибка извлечения; отказ ML; невалидный ответ;
нет пригодных вопросов; ошибка сохранения. Настройки M1/5/MEDIUM/SINGLE_CHOICE.

| № | Шаг | Ожидаемый результат |
|---|---|---|
| 1 | Включить конкретный сбой и запустить. | Создана задача, начинается обработка. |
| 2 | Дождаться завершения. | FAILED с безопасным кодом; quizId готового теста отсутствует; нового теста в списке и БД нет. |
| 3 | Проверить UI. | Понятная ошибка, сохранённые параметры, действия повтора и возврата; нет внутренних ответов ML, ключей и инфраструктурных деталей. |

## TC-GEN-08: Повтор после ошибки (позитивный, мок API/ML)

**Предусловия:** ошибка M2/5/HARD/SINGLE_CHOICE.

| № | Шаг | Ожидаемый результат |
|---|---|---|
| 1 | Восстановить сервис, нажать «Повторить генерацию». | Новый ключ и новая задача, прежние материал и настройки. |
| 2 | Дождаться COMPLETED. | Один результат новой задачи; ошибочная задача не превращается во второй тест. |
| 3 | Отдельно повторить отказ запроса повтора. | UI остаётся в ошибке; настройки сохранены. |

## TC-GEN-09: Возврат к настройкам (позитивный, мок статуса)

**Данные:** M3/5/EASY/TRUE_FALSE.

| № | Шаг | Ожидаемый результат |
|---|---|---|
| 1 | В ожидании нажать «К настройкам». | Выбор восстановлен, серверная задача не отменена. |
| 2 | Завершить прежнюю задачу после ухода. | Нет неожиданного перенаправления с другой страницы. |
| 3 | Независимо вернуться из ошибки. | Материал и настройки восстановлены, их можно изменить. |

## TC-GEN-10: Некорректные параметры (негативный, API)

**Данные, по одному изменению:** questionCount 0/6/11/отсутствует;
difficulty UNKNOWN/отсутствует; questionType UNKNOWN/пустая строка/отсутствует/
массив двух типов; materialId отсутствует. Остальные значения валидны.

| № | Шаг | Ожидаемый результат |
|---|---|---|
| 1 | Отправить каждый вариант POST /api/quizzes. | HTTP 400, валидация на backend. |
| 2 | Проверить БД и счётчик вызовов мока ML. | Новых задач/тестов нет; ML не вызван. |

## TC-GEN-11: Авторизация и владение (негативный, API)

| № | Шаг | Ожидаемый результат |
|---|---|---|
| 1 | Запустить без JWT. | HTTP 401. |
| 2 | От A запустить по M4 пользователя B. | HTTP 404. |

## TC-GEN-12: Ошибка принятия запуска (негативный, мок API)

**Варианты:** HTTP 5xx; сетевой сбой до подтверждения POST.

| № | Шаг | Ожидаемый результат |
|---|---|---|
| 1 | Включить сбой, запустить M1 с валидными параметрами. | Показана ошибка запуска, успех не объявлен. |
| 2 | Вернуться к настройкам. | Материал и параметры сохранены. |
| 3 | При неизвестном исходе повторить тот же запрос с прежним ключом. | Не возникает случайная вторая задача; при необходимости восстановлен исходный jobId. |

## Границы результата

Это описание проверок, не отметка об их прохождении. Для каждого прогона
нужны SHA, настройки, формат/размер, jobId, терминальный код/quizId,
ожидаемый и фактический результат, повторное чтение и оценка качества.
UI с DemoGenerationSource не закрывает интеграционные проверки.
Частичный результат и переход после готовности отмечены как вопросы к PO,
а не молча заменены поведением реализации. В отчёты не включаются ключи,
JWT, пароли, env-файлы или полный inspect контейнеров.
