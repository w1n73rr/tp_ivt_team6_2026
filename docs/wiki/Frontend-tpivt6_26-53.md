## Формы входа и регистрации

Общий AuthShell оформляет тёмно-синюю бренд-панель, белую область формы, вкладки Angular Router и адаптивность по страницам 1–2 «Базовая структура приложения-10.pdf». На auth-маршрутах верхнее меню скрыто, на остальных сохраняется. Содержание dashboard и публичной главной страницы не изменено.
Регистрация: username, email, password, confirmPassword. Подтверждение проверяется на клиенте, в API не отправляется. Поля пароля имеют разные name/id и независимые FormControl, autocomplete=new-password, отдельные кнопки показа. Валидатор группы пересчитывается при изменении любого пароля, без setErrors на дочерних контролах.
POST /api/auth/login: username/password. POST /api/auth/register: username/email/password. AuthService и обработка JWT сохранены.

### Уточнения относительно макета

- Вход называется «Логин»: backend принимает username, поддержка входа по email не заявляется.
- «Забыли пароль?» недоступно и подписано как ещё не реализованное. Google OAuth отсутствует в API и не добавлен.
- Имя в регистрации означает имя пользователя (username), а не отдельное поле ФИО.
- Фирменные векторные значки и фон воспроизведены в коде: исходных Figma-ассетов для этих экранов нет. Ссылка Figma для «Мои материалы» не использовалась как макет auth.
- На узком экране бренд-панель располагается сверху, список преимуществ скрывается, поля и кнопки остаются доступны.
- Переход после входа реализован отдельно в tpivt6_26-54. Эта ветка намеренно основана на dev без включения соседней задачи.
