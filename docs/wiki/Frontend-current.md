# Frontend

## Назначение

Frontend предоставляет интерфейс системы подготовки к экзаменам: регистрацию и вход, работу с учебными материалами, создание тестов, тренировки и просмотр прогресса.

## Технологии

| Технология | Назначение |
| --- | --- |
| Angular 22 и TypeScript | Компоненты и логика приложения |
| Angular Router | Переходы без перезагрузки страницы |
| Reactive Forms и Angular Material | Формы и элементы интерфейса |
| SCSS | Оформление и адаптивность |
| npm | Зависимости, тесты и сборка |
| Docker и Nginx | Сборка, раздача приложения и проксирование API |

## Статус реализации

Задачи 53, 54 и 58 опубликованы и проверены пользователем совместно в dev. Формы подключены к настоящему API авторизации. Новые изменения задач 36 и 35 подготовлены локально в feature-ветках; они используют демонстрационные данные и пока не опубликованы.

**Задачи 36 и 35 остаются в работе.** Для выполнения полного DoD требуется подключение и проверка backend API материалов. Работающий прототип не подтверждает серверное сохранение файла.

## Страницы и маршруты

| Маршрут | Назначение | Состояние |
| --- | --- | --- |
| `/` | Начальная точка приложения | Перенаправляет на `/login` |
| `/login` | Авторизация | Реальный API, после успешного входа переход на `/dashboard` |
| `/register` | Регистрация | Реальный API и клиентская валидация |
| `/dashboard` | Главный экран | Интерфейс реализован, статистика пока недоступна |
| `/materials` | Мои материалы | Локальный прототип задачи 36 |
| `/materials/upload` | Загрузка материала | Локальный прототип задачи 35, зависит от 36 |
| Неизвестный URL | Not Found | Обработка неизвестных маршрутов |

Основная конфигурация находится в `frontend/src/app/app.routes.ts`. Внутренние переходы выполняются через Angular Router. Nginx возвращает `index.html` для клиентских маршрутов, поэтому прямое открытие страницы и F5 работают.

## Вход, регистрация и сессия

Формы оформлены по согласованным макетам. Исправлены масштаб регистрации и адаптивность. Проверяются обязательные поля, email, ограничения длины и совпадение паролей. Пароль и подтверждение вводятся независимо; подтверждение не отправляется на сервер.

Авторизация отправляет `POST /api/auth/login` с `username` и `password`. Регистрация отправляет `POST /api/auth/register` с `username`, `email` и `password`. Ответ содержит `token`. При ошибках API пользователь видит сообщение.

Успешный вход открывает `/dashboard` без полной перезагрузки SPA. JWT хранится в корневом AuthService и сохраняется при переходе между страницами. После F5 токен из памяти теряется. Восстановление сессии, защита маршрутов, передача JWT к API материалов и кнопка выхода требуют отдельной реализации. Google OAuth и восстановление пароля не подключены.

## Главный экран

Отображаются приветствие, быстрые действия, статистика, последняя тренировка и слабые темы. До подключения соответствующих API статистика представлена пустыми состояниями, без выдуманных результатов пользователя.

В новых локальных изменениях главная страница, список и форма материалов используют общую боковую панель, цвета и иконки. Профиль доступен на мобильном экране; на широком экране панель учитывает высоту окна, при нехватке места меню прокручивается. Надпись «Демо-профиль» не означает получение настоящих данных пользователя.

В совместном прототипе доступны переходы к материалам и форме загрузки. Тесты и тренировки ещё не реализованы. Кнопка выхода пока остаётся отдельной будущей задачей.

## Мои материалы — задача 36

Экран перенесён по макету Figma. Для материала отображаются название, формат, размер, предмет и дата. Предусмотрены состояния загрузки, списка, пустого списка и ошибки с повторной попыткой. Переключатель демонстрационных сценариев позволяет проверить эти состояния.

**Сейчас запрос `GET /api/materials` не выполняется.** Список предоставляет локальный MaterialsMock. Предложенный контракт ответа имеет вид `{ "items": [...] }`; интеграция будет проверена после появления API B3.

Редактирование, удаление, скачивание и другие неподключённые действия не изменяют серверные данные. Поиск и фильтрация относятся к задаче 37 и пока не реализованы.

## Загрузка материала — задача 35

Форма оформлена по PDF-макету. Предусмотрены файл, название, предмет, описание и теги. Разрешены PDF, DOCX и TXT. Проверяются обязательные данные, запрещённый формат и пустой файл. «Выберите предмет» является подсказкой, а не доступным вариантом; «Создать предмет» позволяет ввести демонстрационное название.

Во время отправки повторная отправка блокируется. После успешной имитации загрузки запись появляется в списке. При демонстрационной ошибке введённые данные сохраняются для повторной попытки.

**Файл на сервер не отправляется.** В памяти сохраняются только метаданные; после F5 исходный демо-список восстанавливается. Создание предмета также не сохраняется в backend. Реальные успешные ответы и ошибки API ещё предстоит проверить.

## Структура

Основной код находится в `frontend/src/app/`: `features/auth`, `features/dashboard`, `features/materials` и `features/materials/upload`. Общая панель пользовательских страниц — `materials-shell`, демонстрационный источник — `materials.mock`. Изображения макета находятся в `frontend/public/assets/materials`. Роутинг и конфигурация приложения — `app.routes.ts` и `app.config.ts`.

## Запуск и проверки

Для разработки нужны Node.js 24 и npm. В каталоге frontend выполнить `npm ci`, затем `npm start`. Адрес разработки — `http://localhost:4200`. Для реальной авторизации требуется доступный backend и настройка проксирования API; полный сценарий удобно проверять через Compose.

Из корня репозитория:

```bash
npm --prefix frontend run test -- --watch=false
npm --prefix frontend run build
docker compose -f docker-compose.yml -f docker-compose.local.yml up -d --build
```

Приложение в Compose доступно по `http://localhost:3000`. Использовать оба Compose-файла: локальный файл передаёт настройки JWT backend. `.env` и `docker-compose.local.yml` не включаются в коммиты; секреты не публикуются.

Docker запускает образ, собранный из состояния файлов на момент сборки. Переключение Git-ветки не меняет уже запущенный образ. Перед сборкой проверить `git branch --show-current` и `git status --short --branch`.

Автоматизированные проверки совместного прототипа: 32 теста проходят, production-сборка успешна. Ветка 36 отдельно: 26 тестов и успешная сборка. Сборка выдаёт предупреждения о превышении рекомендуемых размеров основного пакета и двух SCSS-файлов; ошибок сборки нет. Проверки моков не заменяют проверку настоящего API.

## Что требуется для завершения

- Backend: API списка и загрузки материалов, окончательный контракт, способ передачи JWT, правила предметов, лимиты файлов и ответы ошибок.
- Интеграция: получение списка, серверная загрузка, повторное чтение после F5, реальные ошибки и подтверждение появления загруженного материала.
- Аналитика: уточнение недостающих макетов и состояний следующих разделов. Для текущей формы используется предоставленный PDF.
- После проверки: публикация feature-веток, PR и ревью по правилам команды. Задачу 37 и ML-задачи 39/40 пока не брали в работу.
