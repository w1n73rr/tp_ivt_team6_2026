# Проверка текущего прототипа

## Как понять, что запущено

Docker не переключает приложение вместе с Git-веткой. Он использует последний собранный образ.

В Git Bash:

```bash
cd /c/tech_prog/project/tp_ivt_team6_2026
git status --short --branch
git switch feature/tpivt6_26-35-material-upload
git branch --show-current
npm --prefix frontend run test -- --watch=false
npm --prefix frontend run build
docker compose -f docker-compose.yml -f docker-compose.local.yml build exam-ai-frontend
docker compose -f docker-compose.yml -f docker-compose.local.yml up -d --no-build exam-ai-frontend
docker compose -f docker-compose.yml -f docker-compose.local.yml ps
```

Это совместный прототип: ветка 35 включает необходимые изменения задачи 36. Задачи остаются отдельными, но форма загрузки использует страницу списка. Для проверки только 36 переключиться на `feature/tpivt6_26-36-materials-page` и повторить сборку frontend. Локальную правку Gradle не добавлять в коммит. Не использовать `git add -A`.

## Маршруты и оформление

1. Открыть `http://localhost:3000`: должна появиться форма входа.
2. Войти: успешный ответ с токеном открывает `/dashboard`; неверный пароль оставляет `/login` с ошибкой. SPA-переход не создаёт новый запрос Document.
3. На главной открыть «Мои материалы», затем форму загрузки. Сравнить боковую панель, цвета и иконки на трёх страницах.
4. Проверить масштаб браузера 100%, 110%, 125%, 150% и 190%, а также ширину 375 и 768 px. Профиль должен оставаться доступным, меню — прокручиваться при необходимости. Не должно быть горизонтального переполнения всей страницы. Масштаб вернуть к 100% после проверки.

## Задача 36 — список

1. Проверить название, формат, размер, предмет и дату материалов.
2. Через демонстрационные сценарии открыть список, пустое состояние и ошибку; проверить повторную попытку.
3. Проверить выбор строк и переход к загрузке в ветке 35.
4. Неподключённые действия не должны выдавать успешное удаление или изменение.
5. В Network сейчас не ожидается GET `/api/materials`: источник моковый.

## Задача 35 — форма

1. Отправить пустую форму: обязательные данные не должны пройти проверку.
2. Выбрать непустой PDF, DOCX или TXT. Проверить автозаполнение названия, предмет, описание и теги.
3. «Выберите предмет» отображается подсказкой и не предлагается как доступный выбор. «Создать предмет» открывает поле названия.
4. Выбрать запрещённый формат и пустой файл: должна появиться ошибка.
5. Отправить допустимые данные. Повторная отправка во время ожидания блокируется. После успеха перейти к материалам: запись появляется в списке.
6. Включить демонстрационную ошибку отправки: данные сохраняются; выключить ошибку и повторить отправку.
7. Обновить страницу: новая запись исчезает, потому что серверного сохранения пока нет. Это ограничение прототипа, а не подтверждение готовности API.

## После появления backend

Проверить реальные GET и запрос загрузки, передачу JWT, принадлежность списка текущему пользователю, сохранение файла и списка после F5, лимиты, ошибки доступа и сервера. Только после интеграции, проверок и ревью закрывать полный DoD 35/36.
