# Интеграционная проверка генерации — 03.11.2026

Код c1bc441 (feature/tpivt6_26-60), дополнительно проверено исправление лимита
SeaweedFS -volume.max=32. Использован отдельный Docker project tpivt-generation-e2e1103:
PostgreSQL 16 и SeaweedFS 4.48 с временными tmpfs-данными; backend доступен только на
127.0.0.1:18881. Пользовательские БД/volumes и существующие контейнеры не изменялись.
Проверенный app.jar упакован поверх существующего локального runtime-образа Java 25.
Это проверка runtime-интеграции, не доказательство чистой сборки Docker из исходников.

## Обнаруженная и исправленная проблема

POST /api/materials дал 503. SeaweedFS сообщил No writable volumes and no free volumes
left при создании collection тестового bucket; свободное место /data при этом было.
Стандартный лимит 8 внутренних volumes оказался исчерпан. После -volume.max=32 и
пересоздания ТОЛЬКО временного хранилища загрузка прошла. Тот же минимальный параметр
добавлен в корневой Compose. Это число внутренних volumes SeaweedFS, не Docker volumes;
параметр не означает немедленное выделение 32 ГБ памяти/диска.

## Реально прошедшие сценарии

- Регистрация двух пользователей и загрузка русского TXT объёмом 21 829 символов через
  backend в настоящее S3-хранилище.
- POST 202 с Location и jobId; повтор тех же параметров/ключа возвращает тот же jobId.
- Другие параметры с тем же ключом — 409; недопустимое количество вопросов — 400.
- HTTP без токена — 401; чужая задача — 404.
- WebSocket: подписка с JWT, терминальный снимок совпадает с HTTP; новая подписка
  после завершения возвращает актуальное состояние. Чужая подписка закрыта кодом 1008.
- Реальный Java ML-адаптер без ключа даёт FAILED/NOT_CONFIGURED; тест не сохраняется.
- Настоящие тестовые PDF и DOCX прочитаны до ML; без ключа заканчиваются NOT_CONFIGURED.
- PDF без текста — DOCUMENT_NO_TEXT. Нечитаемый UTF-8 TXT отклонён ещё на загрузке (400).
- Созданная в ОТДЕЛЬНОЙ тестовой БД orphan RUNNING-задача с истёкшим lease после
  перезапуска backend получила FAILED/GENERATION_INTERRUPTED.

## Реальный вызов модели

Передан ключ через скрытый ввод и временное окружение, модель исключительно
nvidia/nemotron-3.5-super-vl:free. Параметры: 5 / MEDIUM / MULTIPLE_CHOICE,
тот же русский материал. Задача завершилась FAILED/MODEL_UNAVAILABLE.
Ошибка получена через WebSocket и HTTP; в таблице quizzes 0 записей.
Контейнер backend с временной конфигурацией ключа остановлен и удалён.

Проверка Java HTTPS из того же runtime без ключа получила ожидаемый HTTP 401 от
OpenRouter. Сеть в целом доступна, но точная причина ошибки настоящего внешнего
запроса не сохранена адаптером. Не утверждается, что причиной было качество модели.
