# Подключение ML-компонента: короткая памятка BE и FE

Статус: компонент реализован в feature/tpivt6_26-64-ml-generator от dev.
M1 v2 выбран PO 02.11.2026: см. ml-output-m1-v2.md. BE/FE подтверждают подключение.
Публичный обмен статусами требует согласования команды.
WebSocket, очередь задач и SQL этим компонентом не реализованы.
Готовность: локальные unit-тесты и сборка прошли; реальная серия 02.11 содержит
таймаут/нештатное завершение и замечания по смыслу вопросов. Компонент можно изучать
и подключать, но карточка пока не Done. См. docs/ml-examples/live-review-2026-11-02.json.

## Что вызывает BE

Spring bean `tech.genna.TY3.ml.QuizGenerator`, созданный `MlConfiguration`.
Внедряется через конструктор, как другие зависимости сервисов проекта.

```java
GenerationRequest request = new GenerationRequest(
    jobId.toString(), materialId.toString(), extractedText,
    questionCount, difficulty, questionType);

Quiz quiz = generator.generate(request, event -> {
    // BE: быстро зафиксировать/поставить в очередь уведомление о новом этапе.
    // Не ждать здесь доставки сообщения через WebSocket.
});
// BE: сохранить quiz. После успешного commit установить COMPLETED/quizId.
```

`difficulty` — GenerationRequest.Difficulty: easy, medium, hard.
`questionType` — GenerationRequest.QuestionType: single_choice, multiple_choice, true_false.
Число — 5/10. Текст уже извлечён, непустой, не более 60000 символов.
requestId/jobId и materialId — строки до 100 символов. Пути и файлы не передаются.
Исходные пользовательские enum/DTO BE преобразует на границе в эти типы.

## Асинхронность — точно

- generate — БЛОКИРУЮЩИЙ метод. Он возвращает Quiz только после ответа и проверки.
- onProgress — СИНХРОННЫЙ callback. Генератор вызывает accept(event) и ждёт его возврата.
- Обработчик может вызываться из потока generate или сетевого потока адаптера.
  Нужен потокобезопасный быстрый обработчик, а не запись в медленный сокет.
- BE запускает generate в ограниченном фоновом исполнителе. Submit HTTP-запрос
  создаёт задачу и быстро возвращает 202/jobId, не ожидает модель.
- Внутри клиента есть служебный виртуальный поток для чтения и общего таймаута,
  но это НЕ делает generate асинхронным для вызывающего BE.
- Не держать SQL-транзакцию/блокировку строки всё время ожидания модели.

Шаблон и JSON входа собираются внутри generate. OpenRouterClient вызывает API
со stream=true. Ключ — OPENROUTER_API_KEY на сервере; в frontend его нет.
Модель задаётся OPENROUTER_MODEL, разрешены явные :free варианты; платного fallback нет.

## Что получает BE

При успехе — Quiz, M1 v2 (schemaVersion, materialId, title, questions).
Правильные ответы — массив correctOptionIds, а не старое поле correctOptionId.
При ошибке — GenerationFailure.code(), связывается с исходным jobId.
Тексты провайдера, ключ и исходная лекция в пользовательскую ошибку не попадают.

Событие: GenerationEvent(requestId, stage, sequence). Sequence локален одному вызову.
PREPARING_PROMPT → WAITING_FOR_MODEL → RECEIVING_RESPONSE → VALIDATING → REVIEWING_CONTENT → VALIDATED.
REVISING означает одну исправляющую попытку; этапы запроса и проверки могут повторяться.
Показывайте REVIEWING_CONTENT как «Проверяем содержание», REVISING — «Исправляем тест».
При отказе — FAILED. RECEIVING_RESPONSE означает первое содержимое ответа,
а не число готовых вопросов и не непрерывный процент.
VALIDATED — только ML-часть завершена; COMPLETED назначает BE после сохранения.

Ошибки слушателя изолированы генератором: не повторять вызов модели из-за разрыва UI.
BE отвечает за сохранение текущего состояния и доставку; WebSocket — не база данных.

## Что делает FE для WebSocket (предложение, не готовый протокол)

1. Через HTTP запускает генерацию, получает jobId.
2. Открывает соединение WebSocket с BE и подписывается на этот jobId.
3. BE проверяет пользователя и владельца задачи. Не доверять jobId от клиента.
4. Сразу читает HTTP-снимок задачи: события могли прийти до подписки.
5. Обрабатывает сообщения состояния и обновляет этап/индикатор. Более старая
   внешняя version не должна затирать более новую.
6. При разрыве переподключается и повторно читает снимок. Модель заново не запускает.
7. COMPLETED + quizId → сообщение «Тест готов» и таблица тестов (TY5, без прохождения).
   FAILED → безопасная причина, возврат к настройкам и осознанный повтор.

В браузерном JS соединение открывает `new WebSocket(url)`, сообщения получает
обработчик `message`. Это код FE. BE принимает соединение и отправляет JSON-состояния.
Единственный endpoint, формат подписки и вид авторизации согласуют BE/FE.
Браузерный конструктор не позволяет произвольно добавить HTTP Authorization header:
при текущей JWT-авторизации это нужно учесть, а не писать пример, который не работает.
Токен не помещать в URL. В production нужен wss:// и проверка Origin.

Ни Kafka, ни поток OpenRouter не подключают браузер автоматически.
Пока WebSocket работает, периодический опрос не обязателен. GET нужен при открытии,
переподключении и как согласованный fallback. Другие запросы сервера продолжают работать.

## Три согласования перед интеграцией

1. Подключить GenerationRequest и выбранный Quiz/M1 v2, включая 2–3 верных для multiple_choice.
2. Подтвердить callback этапов и границу: ML — генерация, BE — задача/фоновый запуск/БД.
3. BE+FE+Analyst утвердить WebSocket/авторизацию/состояния по generation-lifecycle-proposal.md.

В текущем OpenAPI успех называется COMPLETED, progress пока обязательный integer:
предлагаем убрать обязательный процент/разрешить null. Эти поля здесь не изменены.
После подключения проверить реальный вызов BE → ML и обработку ошибки, затем весь TY5.

## Как устроен промпт (для разработчика и его агента)

BE не должен собирать промпт или вызывать OpenRouter параллельным способом.
Внутри QuizGenerator постоянный system-текст читается из `ml/prompt.txt`:
роль преподавателя, опора только на материал, охват, сложности, правила выбранного типа,
точный формат M1 v2 и ответ при недостаточном материале.
Второе сообщение user собирается через JSON-сериализацию из параметров метода:

```json
{"requestId":"job-id","settings":{"questionCount":5,"difficulty":"medium",
"questionType":"single_choice"},"material":{"id":"material-id","text":"извлечённый текст"}}
```

Весь текст передаётся целиком (до установленного лимита), без RAG/векторов и истории чатов.
OpenRouterClient добавляет model, stream=true, temperature=0.2, max_tokens и ключ из окружения.
Ключ и настройки HTTP не являются частью учебного текста или system-промпта.
Поток content собирается, затем проверяется валидатором. Формат модели не равен статусу задачи BE.
Если адаптер сменится, контракт generate и callback могут остаться прежними.

## Короткое сообщение команде

Генератор принимает текст и настройки и сам собирает промпт. Передайте ему также ID материала
и задачи. Он вернёт Quiz/M1 v2 либо ошибку. Запускайте generate в фоне: он ждёт модель.
Вторым аргументом передайте быструю функцию приёма этапов. Она получает новый этап,
BE сохраняет его и ставит сообщение для WebSocket; frontend получает JSON-состояние
с jobId и меняет надпись. После возврата Quiz BE сохраняет тест и только после commit
устанавливает COMPLETED. Генератор не управляет WebSocket, SQL и пользовательскими HTTP-запросами.

## Ограничения цикла генерации

Обычный запуск делает два вызова модели: генерация и проверка содержания. При
конкретных дефектах допускается одна исправляющая попытка (всего до четырёх вызовов).
Сетевые ошибки автоматически не повторяются. Весь generate ограничен 240 секундами,
отдельное обращение — 90 секундами; оба значения настраиваются окружением.
Новые безопасные коды: MODEL_OUTPUT_LIMIT, MODEL_REFUSED, QUALITY_REJECTED.
Проверка содержания моделью не гарантирует безошибочность. Контракт входа и Quiz не изменён.

При валидационной ошибке исправляющий запрос включает безопасную конкретную
причину, например questions[0].correctOptionIds: требуется 2 или 3 ответа.
Это внутренние данные для модели, не сырой ответ провайдера пользователю.
