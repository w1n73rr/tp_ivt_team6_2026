## Граница компонента

`tech.genna.TY3.ml.QuizGenerator` — Spring bean, создаваемый конфигурацией `MlConfiguration`.
Зависимости передаются конструктором. `ModelClient` — заменяемый адаптер провайдера.
OpenRouter вызывается стандартным Java HttpClient; новая библиотека/Spring AI не требуется.
Это соответствует текущему Spring Boot 4 / Java 25 проекта и не меняет его сборочный стек.
Извлечение PDF/DOCX/TXT, авторизация, задачи, WebSocket, SQL и CRUD не реализуются модулем.

Параметры: requestId/materialId — непустые строки до 100 символов (UUID backend можно передать
через toString), текст — непустой, до ML_MAX_INPUT_CHARS (максимум 60000), число — 5/10,
сложность — easy/medium/hard, тип — single_choice/multiple_choice/true_false.
Никакие пути к файлам не принимаются. Лимит символов — ограничитель нагрузки, не точный счётчик
токенов. Текст не обрезается и не делится на фиксированные части. Превышение лимита — INVALID_INPUT.

## События и streaming

PREPARING_PROMPT → WAITING_FOR_MODEL → RECEIVING_RESPONSE → VALIDATING → REVIEWING_CONTENT → VALIDATED.
При исправлении кандидата появляется REVISING, затем повторяются этапы запроса и проверки.
При ошибке — FAILED и исключение GenerationFailure с безопасным code().
RECEIVING_RESPONSE появляется при первом непустом content, не при reasoning/keepalive.
События содержат requestId, этап и возрастающий номер в рамках одного вызова.
Не содержат текста лекции, ключа, правильных ответов, процентов или частичного JSON.
VALIDATED означает только завершение ML. Сохранение ещё не выполнено.

Обработчик вызывается синхронно; он должен быстро передавать событие в механизм BE.
generate блокирует вызывающий поток. Callback может выполняться в потоке generate
или сетевом потоке адаптера; обработчик BE должен быть потокобезопасным.
Его исключение изолировано: разрыв UI не провоцирует повторный вызов модели. BE отвечает
за доставку/журналирование, права владельца, восстановление соединения и актуальный статус.
Не хранить единственный источник истины о задаче только в WebSocket-соединении.
Нет фиксированной периодичности событий: генерация может занимать время без смены этапа.
Heartbeat WebSocket при необходимости реализует BE отдельно от ML-прогресса.

OpenRouter получает stream=true. Адаптер собирает SSE data, игнорирует комментарии и reasoning,
проверяет HTTP и ошибки внутри потока, требует finish_reason=stop и [DONE].
Обрезанный ответ/finish_reason=length не считается успешным.
Имеется общий таймаут на заголовки и весь поток, предел размера ответа.
Автоматических повторов сетевой ошибки и платного fallback нет. После полностью полученного
ответа допустима одна исправляющая генерация: при невалидном JSON либо конкретных
замечаниях проверки содержания. Обычный цикл — два обращения (генерация и проверка),
максимум — четыре. Общий срок всего generate — ML_TOTAL_TIMEOUT_SECONDS (240 с),
отдельного обращения — OPENROUTER_TIMEOUT_SECONDS (90 с).
Reasoning по умолчанию отключён через OPENROUTER_REASONING_ENABLED=false, чтобы
скрытые рассуждения не расходовали лимит ответа. Провайдер должен поддерживать этот параметр. Уход пользователя со страницы не отменяет задачу.

## Формат и качество

M1 v2: Quiz(schemaVersion=2, materialId, title, questions).
Question: id, type, text, options[{id,text}], correctOptionIds[], explanation.
single_choice — 4 варианта a–d, 1 правильный; multiple_choice — 4, 2–3 правильных;
true_false — true/«Верно», false/«Неверно», 1 правильный; в тесте оба значения ответа.
Старый correctOptionId и старые DTO/контроллеры не меняются; адаптацию согласовать с BE.
Модель возвращает оболочку requestId/status/quiz или requestId/status/error;
валидатор проверяет связь с входом, метод возвращает только проверенный Quiz.
GenerationFailure не содержит сырого ответа провайдера; BE связывает его с исходным requestId.

Проверяются обязательные и лишние поля, количество, тип, ID, ответы, непустые тексты,
точные нормализованные повторы вопросов и вариантов. Ноль/частичный набор не допускается.
Варианты перемешиваются программой с сохранением связи правильных ответов.
Отдельный шаблон ml/review-prompt.txt проверяет кандидата по исходному материалу.
Это проверка той же моделью, которая тоже может ошибаться; она не заменяет приёмку.
После повторного отклонения возвращается QUALITY_REJECTED.
Не доказаны автоматически: фактическая правильность, смысловые повторы, честность сложности,
отсутствие нескольких верных вариантов и охват материала. Нужна содержательная приёмка.

Коды: INVALID_INPUT, NOT_CONFIGURED, RATE_LIMITED, MODEL_UNAVAILABLE, MODEL_TIMEOUT,
INVALID_MODEL_OUTPUT, MODEL_OUTPUT_LIMIT, MODEL_REFUSED, QUALITY_REJECTED,
INSUFFICIENT_MATERIAL, CANCELLED. Системная отмена не равна уходу со страницы.
