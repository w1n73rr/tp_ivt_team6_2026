# Первичная проверка перед PR задачи85

## Проверено

- На каждый push и ручной запуск первым выполняется Gitleaks8.30.1 по всей истории
  текущего SHA. Сканер закреплён на версии; Linux-архив проверяется по SHA256.
- Значения находок скрываются `--redact=100`. Секреты не загружаются в артефакты.
  Ошибка сканера или найденный секрет блокируют выбор остальных заданий и публикацию.
- Единственное исключение — точный fingerprint исторического JWT-плейсхолдера
  в dotenv-примере `backend/MATERIALS.md`, а не весь файл или тип секрета.
- Git игнорирует `.env*`, кроме шаблонов, локальный Compose, PEM/KEY и хранилища ключей.
  Docker-контексты также исключают эти файлы. Уже отслеживаемые файлы правилами
  ignore не удаляются: их дополнительно проверяет история Git.
- `.env.example` содержит только значения для локальной разработки.
  `.env.ci.example` — открытые значения одноразового тестового окружения.
- В CI PostgreSQL и S3 используют tmpfs; их порты и порт backend не публикуются
  через CI-дополнение Compose. Тестовый frontend доступен на loopback.
- Публикация GHCR ждёт успеха интеграции. Право `packages: write` выдано только ей.

## Границы этой проверки

Отсутствие находок Gitleaks не доказывает отсутствие всех секретов и уязвимостей.
Сканер работает после отправки в GitHub: настоящий утёкший ключ нужно немедленно
отозвать, а не только удалить из следующего коммита. Рекомендуется также локальный
сканер перед push и доступная защита от секретов на сервере репозитория.

До публичного deployment ещё нужны:
- Отдельные секреты сервера без демонстрационных JWT/паролей из шаблонов.
- Проверка авторизации, загрузок файлов, зависимостей и состава финальных образов.
- Настройка сети и firewall: наружу не должны открываться PostgreSQL и S3.
- Постоянные данные, резервная копия и проверенное восстановление.
- План обновления и отката с учётом необратимых миграций БД.
- Защищённый транспорт либо явно ограниченный учебный HTTP-стенд только с тестовыми данными.

Номера портов не являются секретами. Изоляция доступа важнее сокрытия номеров.
Текущие локальные настройки и успешный CI не являются готовой production-конфигурацией.
Основная БД и её volumes этой проверкой не изменяются.
