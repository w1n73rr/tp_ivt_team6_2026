# M1 v2 — формат результата ML

02.11.2026: Product Owner выбрал этот формат для реализации ML. Он передаётся BE/FE
для подключения и отображения. Это не утверждение схемы БД или уже проверенной интеграции.

Метод `generate` возвращает Java-объект `Quiz`. Его JSON-представление:

```json
{
  "schemaVersion": 2,
  "materialId": "UUID-или-строка-материала",
  "title": "Название теста",
  "questions": [
    {
      "id": "q1",
      "type": "single_choice",
      "text": "Текст вопроса",
      "options": [
        {"id": "a", "text": "Вариант A"},
        {"id": "b", "text": "Вариант B"},
        {"id": "c", "text": "Вариант C"},
        {"id": "d", "text": "Вариант D"}
      ],
      "correctOptionIds": ["b"],
      "explanation": "Краткое обоснование по материалу"
    }
  ]
}
```

Пример показывает форму одного вопроса, не полный валидный тест: полный результат
содержит ровно 5 или 10 вопросов в соответствии с входом.

| Поле | Тип и правило | Обязательность |
|---|---|---|
| schemaVersion | integer, ровно 2 | Да |
| materialId | string, непустая, до 100 символов, совпадает с входом | Да |
| title | string, непустая, до 4000 символов | Да |
| questions | array, ровно запрошенные 5/10 элементов | Да |
| questions[].id | string, q1…qN по порядку, уникальные | Да |
| questions[].type | string: single_choice/multiple_choice/true_false, один тип всего запуска | Да |
| questions[].text | string, непустая, до 4000 символов | Да |
| questions[].options | array объектов id/text, правила ниже | Да |
| options[].id | string: a–d либо true/false, уникальные внутри вопроса | Да |
| options[].text | string, непустая, до 4000 символов | Да |
| correctOptionIds | array уникальных строковых id вариантов своего вопроса | Да |
| explanation | string, непустая, до 4000 символов | Да |

single_choice: четыре варианта a–d, ровно один правильный.
multiple_choice: четыре варианта a–d, ровно два или три правильных.
true_false: ровно true/«Верно» и false/«Неверно», один правильный на вопрос;
в тесте должны присутствовать оба значения правильного ответа. Примерно равное
распределение запрашивается промптом; минимум одно каждого проверяет валидатор.

Лишние поля запрещены. Проверяются ссылки ответов, тип, число, пустые строки,
повторные ID и нормализованные текстовые дубли. Варианты a–d перемешиваются кодом
с сохранением правильных ответов. Структурная валидация не доказывает качество/истинность.

Схема оболочки ответа модели: backend/src/main/resources/ml/result-v2.schema.json;
эквивалентная проверка с привязкой к входным параметрам — QuizValidator.
Модель возвращает requestId/status/quiz либо requestId/status/error. Эта оболочка
разбирается внутри ML и не заменяет публичную задачу генерации backend.
Метод возвращает Quiz либо GenerationFailure, связанный BE с его исходным jobId.

question/option id локальны одному результату, это НЕ primary key PostgreSQL.
BE создаёт собственные ID и сохраняет связи через свой механизм записи. При наличии
пользовательского названия BE применяет согласованные правила имени в своём DTO;
предел M1 не отменяет ограничения интерфейса/БД. Новые таблицы этим форматом не задаются.
Правильные ответы не выдавать в списке тестов или неподходящем публичном DTO.

Далее требуется подтверждение BE/FE, что результат подключён без потери полей,
а также интеграционная проверка. Одно решение PO не считается доказательством этой проверки.
