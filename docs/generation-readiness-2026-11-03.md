## Реальный успех backend

Изолированный PostgreSQL + SeaweedFS + актуальный локально собранный backend JAR. Это упаковка готового JAR поверх локального runtime-образа, не чистая сборка полного Compose с нуля. Пользовательская БД и существующие контейнеры не менялись. Тестовая лекция №1 о моделировании загружена через настоящий API как TXT; 5 вопросов, MEDIUM, SINGLE_CHOICE; nvidia/nemotron-3.5-super-vl:free, без заглушки ответа.

Пройдены:

- регистрация тестовых пользователей и загрузка в S3 через backend;
- POST возвращает 202, задача выполняется в фоне;
- повтор с тем же ключом возвращает ту же задачу; другие параметры — 409, недопустимое количество — 400;
- HTTP без авторизации — 401, чужая задача — 404;
- этапы и терминальный статус получены через настоящий WebSocket; восстановление подписки совпадает с HTTP-снимком; чужая подписка закрыта кодом 1008;
- результат настоящей модели сохранён, COMPLETED содержит quizId, в реальном API списка ровно один соответствующий тест с пятью вопросами;
- SQL-проверка подтверждает пять сохранённых вопросов и правильные связи UUID ответов; ключи ответов отсутствуют в summary/статусе.

Подтверждение: [машиночитаемый отчёт и сохранённый тест](ml-examples/backend-success-0346e02.json). В отчёте нет API-ключа, JWT или паролей; UUID относятся к удалённому временному стенду. Стенд после проверки остановлен и удалён.

Ручная проверка сохранённого теста: ключи опираются на лекцию. Часть вопросов — прямое воспроизведение, правильные варианты часто длиннее остальных, поэтому строгое соответствие всей серии MEDIUM не подтверждено. Один успешный прогон не отменяет предыдущие MODEL_UNAVAILABLE, таймауты и смысловые дефекты hard.

## Можно ли закрывать BE-60

Пока нет по полному DoD. Реальный успешный путь теперь подтверждён для TXT и одной комбинации настроек. Извлечение PDF/DOCX/TXT и ошибки документов проверялись отдельно; полный успешный путь с реальной моделью для PDF/DOCX и конкурентные запросы на настоящей БД в этой серии не проверены. Предыдущие локальные 54 выбранных unit-теста и bootJar — локальные результаты, не CI. Нужны подтверждённые согласования контрактов/статусов и качество ML для заявленных настроек. Само отсутствие готовой FE-формы не является дефектом BE: backend можно принимать отдельно по его API и DoD.

Нужны PR и его ссылка в артефактах, человеческий аппрув и комментарий ревьюера, зелёный CI на проверяемой версии, повторение сценария другим участником по README. Публикация/merge/карточки в этой проверке не выполнялись. После merge — повторная проверка целевой ветки и удаление завершённой ветки.

## Можно ли закрывать FE-66

Нет. В актуальном dev:

- frontend/src/app/features/generation/generation-source.ts предоставляет DemoGenerationSource; start возвращает DEMO_WAITING, а не реальную задачу;
- generation.ts переводит sending в waiting; ready выставляется demoResult, не по подтверждённому COMPLETED/quizId;
- generation.html явно сообщает о демонстрации и отсутствии сохранённого теста;
- tests/tests-source.ts предоставляет DemoTestsSource с массивом фиктивных строк вместо GET /api/quizzes.

Форма/состояния визуально подготовлены, но обязательные AC реального сохранения, списка и сквозного BE+ML не выполнены. Нужны HTTP-адаптеры параметров/запуска/списка, доставка статуса и восстановление, переход к таблице только после COMPLETED с quizId, тесты и сквозная проверка. Это отдельная работа FE, она в ходе аудита не реализовывалась.

## Передача доступа тестировщику

На общем стенде OPENROUTER_API_KEY задаёт обслуживающий backend участник через локальный env/секреты развёртывания. Ключ не передаётся frontend и не публикуется в карточке, PR, Swagger, логах или этом отчёте. Тестировщик регистрирует свою тестовую учётную запись и получает собственный Bearer JWT через штатный вход; JWT также не публикуется. Для отрицательных проверок используются две отдельные тестовые учётные записи.

Для собственного локального стенда тестировщик отдельно получает provider key по закрытому каналу или использует свой, задаёт OPENROUTER_API_KEY в игнорируемом env; шаблон .env.example содержит только безопасные значения. Текущий .env.ml.local автора не включается в артефакты. При бесплатной модели платных запасных маршрутов нет. Порядок API-вызовов и подписки: backend/GENERATION.md.
