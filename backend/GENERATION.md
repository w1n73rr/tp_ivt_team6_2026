# TY5: генерация теста

Backend вызывает подтянутый Java-пакет `ml` через `QuizGeneratorAdapter`.
В `QuizGenerator.generate(request, callback)` передаются jobId как requestId,
materialId, извлечённый текст и настройки count/difficulty/type. Промпт,
OpenRouter streaming и проверка M1 v2 находятся внутри ML-пакета.
Проверки запускаются локально и в CI отдельно от реального вызова модели.
Unit-тесты не требуют ключа OpenRouter и пользовательской базы данных.

## API

`202` + ID задачи, WebSocket для изменений и HTTP-снимок для открытия/восстановления.
При недоступности WebSocket допустим polling раз в 2 секунды. UUID
`Idempotency-Key` защищает повтор запроса 24 часа. HTTP требует Bearer JWT;
WebSocket проверяет JWT и владельца при подписке.

- `GET /api/quizzes/generation-options`: серверный справочник 5/10 вопросов,
  EASY/MEDIUM/HARD, SINGLE_CHOICE/MULTIPLE_CHOICE/TRUE_FALSE.
- `POST /api/quizzes`: задача по одному собственному сохранённому материалу.
  Возвращает `202`, `GenerationJob`, `Location: /api/generation-jobs/{id}`.
  Извлечение/ML выполняются в фоне; статус READY материала не требуется.
- `GET /api/generation-jobs/{id}`: только собственная задача, иначе 404.
  Терминальная ошибка задачи находится в теле HTTP 200, без JWT — HTTP 401.
- `GET /api/quizzes`: собственные сохранённые тесты в `items`, без ключей ответа.
  Summary дополнен `format` и `questionType` для существующей таблицы.

Пример PowerShell 7: `$token` — из входа/регистрации, `$materialId` — из списка
материалов этой же учётной записи:

```powershell
$headers = @{ Authorization = "Bearer $token"; 'Idempotency-Key' = [guid]::NewGuid().ToString() }
$payload = @{ materialId = $materialId; name = 'Проверка материала'; questionCount = 5; difficulty = 'MEDIUM'; questionType = 'SINGLE_CHOICE' } | ConvertTo-Json
$job = Invoke-RestMethod -Method Post -Uri http://localhost:8080/api/quizzes -Headers $headers -ContentType 'application/json' -Body ([Text.Encoding]::UTF8.GetBytes($payload))
do {
    Start-Sleep -Seconds 2
    $state = Invoke-RestMethod -Uri "http://localhost:8080/api/generation-jobs/$($job.id)" -Headers $headers
    $state | Select-Object id,status,stage,detailStage,version,quizId,error
} while ($state.status -in @('QUEUED','RUNNING'))
Invoke-RestMethod -Uri http://localhost:8080/api/quizzes -Headers $headers
```

При неизвестном исходе POST повторяйте **те же** headers/payload, включая UUID.
Для намеренной новой генерации после FAILED создавайте новый ключ.
Нормализация: trim имени, имя по умолчанию «Тест», язык ru, один questionType.
Одинаковые параметры с тем же ключом в течение 24 часов возвращают исходную задачу,
другие параметры — `409 IDEMPOTENCY_KEY_REUSED`. Область ключа — владелец и этот
endpoint. Непустые topicIds/true у персонализации отклоняются до постановки/ML.

## Надёжность и извлечение

Flyway V4 из dev создаёт справочник параметров; V6 создаёт generation_jobs/quizzes, V7 добавляет этапы/версию. Принятые миграции dev не изменены.
Сохраняются снимки параметров, материала, предмета, формата и fileId.
POST не вызывает S3/ML. Приём/удаление сериализованы блокировкой владельца;
материал с QUEUED/RUNNING нельзя удалить.

Worker фиксирует RUNNING с token через `FOR UPDATE SKIP LOCKED`. Генерация идёт
в ограниченном executor (по умолчанию 2 потока), очередь остаётся в PostgreSQL.
S3/парсер/ML работают вне транзакции БД. Завершение сверяет token и RUNNING,
поэтому поздний результат не меняет терминальную задачу.
Lease и срок всего job задаёт GENERATION_JOB_TIMEOUT_SECONDS (1–3600 с).
Значение 0 по умолчанию означает max(300, ML_TOTAL_TIMEOUT_SECONDS + 120).
В этот срок входят чтение файла, извлечение, модель и обработка результата.
GenerationWatchdog использует собственный scheduler и раз в секунду проверяет
активные задачи/истёкшие lease, не занимая generationExecutor. Поэтому занятый
пул генерации не блокирует фиксацию FAILED/GENERATION_INTERRUPTED.
Watchdog прерывает поток и вызывает abort текущего S3-чтения. Остановка вычислений
кооперативная: сторонний парсер, игнорирующий interruption, может продолжить работу,
но его поздний результат не сохраняется. Небезопасная принудительная остановка
потока не используется; число рабочих потоков остаётся ограниченным.
После сбоя процесса истёкшая задача становится FAILED/GENERATION_INTERRUPTED;
неизвестно завершившийся запрос к модели автоматически не повторяется.
Новая попытка требует осознанного POST с новым ключом. ML ограничивает общую
длительность своим ML_TOTAL_TIMEOUT_SECONDS (по умолчанию 240 с), S3 — 60 с.

Callback синхронный, поэтому он только кладёт событие в ограниченную очередь
без SQL/сокетов. Отдельный обработчик сохраняет detailStage и увеличивает version.
sequence привязан к одному вызову: события чужого requestId, устаревшей попытки
или с меньшим sequence не меняют состояние. Внешний version хранится в БД и
не сбрасывается. VALIDATED означает конец ML, затем SAVING и атомарный COMPLETED.

PDF: [Apache PDFBox](https://pdfbox.apache.org/3.0/getting-started.html).
DOCX: ZIP с лимитами + SAX без DTD/внешних сущностей. TXT: строгий UTF-8.
Лимиты: файл 10 MiB, PDF 10 страниц, текст 30000 Unicode code points,
распакованный DOCX 20 MiB/2048 entries. Пустой текст/скан без текста — ошибка;
зашифрованный PDF/Office и DOCX с documentProtection — ошибка защиты. OCR нет.
Word сохраняет w:tab как табуляцию, w:br/w:cr как перенос строки. Проверочный
документ в одном абзаце: Java → tab → Python → br → 4 → br → 5.
Результат: `Java\tPython\n4\n5`; слова и числа не склеиваются.

Результат ML требует совпадающий jobId, точное число вопросов, выбранный тип,
непустые уникальные вопросы/варианты и корректный ключ ответа. SINGLE_CHOICE:
4 варианта/1 правильный; MULTIPLE_CHOICE: 4/2–3; TRUE_FALSE: 2/1.
Массив correctOptionIds и объяснения сохраняются. Локальные q1/a/true из M1
не используются как ключи БД: SavedQuiz создаёт UUID вопросов/вариантов и
переносит ссылки правильных ответов на новые UUID, сохраняя исходные sourceId.
Ключи и объяснения хранятся приватно. `GenerationStore.saveQuiz` — единая точка
сохранения. UNIQUE quizzes.job_id и блокировка задачи исключают дубль доставки.
Вставка теста и COMPLETED фиксируются атомарно; ошибка БД откатывает обе операции.
После ошибки фиксации worker отдельно перечитывает задачу под блокировкой и
записывает FAILED/GENERATION_FAILED, только если задача ещё RUNNING и claim token
принадлежит этому worker. Уже сохранённый COMPLETED не перезаписывается даже при
потере подтверждения commit. Если БД недоступна и запись FAILED не удалась,
задачу завершает механизм истечения срока после восстановления БД. Модель повторно
автоматически не вызывается.
Терминальные задачи игнорируют повторный результат.

Без OPENROUTER_API_KEY генератор вернёт NOT_CONFIGURED. В API возвращаются только
allowlisted коды и безопасные сообщения без текста провайдера/лекции/ключей.
OPENROUTER_MODEL/TIMEOUT_SECONDS/MAX_OUTPUT_TOKENS/REASONING_ENABLED,
ML_TOTAL_TIMEOUT_SECONDS и ML_MAX_INPUT_CHARS описаны в .env.example.
GENERATION_WORKER_DELAY_MS=1000 — задержка диспетчера, GENERATION_WORKERS=2 —
число фоновых потоков (1–16). Частота клиентского polling от них не зависит.

## WebSocket backend

Endpoint: `/api/ws/generation` (ws:// локально, wss:// при HTTPS).
Origin проверяется по APP_CORS_ALLOWED_ORIGINS. Токены и параметры в URL запрещены.
За 10 секунд клиент отправляет единственный кадр:

```json
{"type":"SUBSCRIBE","token":"<JWT без Bearer>","jobId":"<UUID>"}
```

Backend проверяет JWT/владельца, отправляет актуальный GenerationJob и далее
снимки с новыми version. Состояние БД для подписок проверяется с интервалом
GENERATION_WEBSOCKET_POLL_MS (по умолчанию 2000 мс вместо прежних 250 мс).
Это серверный polling сохранённых снимков, а не прямой push из транзакции;
изменение может дойти до клиента с задержкой порядка интервала плюс доставка.
Короткие этапы могут объединяться: последнее
сохранённое состояние является источником истины. progress до успеха отсутствует;
проценты из этапов не вычисляются. Ping каждые 15 секунд держит соединение.
Доставка идёт в отдельном ограниченном executor, медленный клиент не блокирует ML.
Истёкший JWT/чужая задача/некорректный кадр закрывают соединение кодом 1008,
терминальный снимок — кодом 1000. Правильные ответы в снимки не включаются.
Проксирование Upgrade настроено в frontend/nginx.conf; FE-экран в этом шаге
не подключался. После открытия/переподключения клиент также читает HTTP-снимок,
принимает только более новую version и не запускает модель заново.

## Проверки исправления надёжности

Из backend: `./gradlew test --tests 'tech.genna.TY3.ml.*' --tests 'tech.genna.TY3.service.generation.*' --tests 'tech.genna.TY3.controller.GenerationControllerTest' bootJar`.
Из корня: `python -m unittest discover -s ci -p 'test_*.py'`.
Watchdog-тест занимает все worker slots и имитирует игнорирование interruption;
очистка и запрос остановки всё равно выполняются. Worker-тест не допускает
сохранения результата, вернувшегося после общего дедлайна. Проверяются orphaned
claims, завершённая задача и ограничения конфигурации. Smoke-проверка без ключа
ожидает NOT_CONFIGURED; другой код или сохранённый тест дают провал.

Эти проверки не заменяют полный сценарий PostgreSQL + S3 + OpenRouter + WebSocket.
Историческое ограничение первого прогона: Docker Engine был недоступен. Последующие реальные проверки и успешный TXT-сценарий описаны ниже.

Smoke-клиент по умолчанию ждёт 450 с. При увеличенном общем лимите/очереди задайте
`tests/checks/generation-check.mjs --timeout ...` больше ожидаемого времени задачи с очередью.

Локально 03.11.2026 прошли 68 выбранных Java unit-тестов (ML, генерация и соседние
сервисы), 10 Python unit-тестов, bootJar и проверка конфигурации Compose. Это не CI.
Позднее подтверждён реальный успешный TXT-сценарий на PostgreSQL/S3/OpenRouter/WebSocket; см. отчёт ниже. Это не подтверждение всех форматов и настроек.
Текущие промпты без изменений собраны для обсуждения в [ML-PROMPTS.md](ML-PROMPTS.md).

Промпты генерации/проверки и программные инструкции исправления теперь английские.
Материал передаётся на исходном языке; текст теста и объяснения — на русском,
JSON/ID/типы остаются M1 v2. Пользовательский параметр нового языка не вводился.
Проверяющему явно объяснена разница между неверным дистрактором и ошибкой ключа.
Реальный эффект этих изменений должен подтверждаться отдельно от unit-тестов.

Реальный прогон английских инструкций на прежнем русском материале, Super VL free,
10 / medium: single_choice — INVALID_MODEL_OUTPUT на проверяющем (18.69 с),
multiple_choice — MODEL_TIMEOUT на проверяющем (101.41 с), true_false — прошёл
за 5.07 с, ключи подтверждены исходником, но соответствие medium не доказано.
Итог серии красный; улучшение качества не заявляется. Метаданные:
[english-prompt-review-2026-11-03.json](ML-QUALITY.md).

## Совместимость с API запуска BE-60

Ветка BE-60 объединена с dev 8c94b25. Для запуска используется единственный `POST /api/quizzes`, без прежней заглушки 501. Вход содержит `materialId`, `questionCount`, `difficulty`, `questionType`; имя опционально. Новый endpoint `/api/generation/parameters` сохранён. Прежний `/api/quizzes/generation-options` возвращает проекцию того же SQL-справочника с фильтрацией недоступных значений, без отдельного набора defaults в коде.

В одной транзакции новой задачи проверяются значения по GenerationParametersService, сохраняется generation_settings_snapshots и создаётся job. При ошибке поиска собственного материала снимок откатывается. Идемпотентный повтор возвращает исходную задачу до повторной проверки изменяемого справочника: принятое решение не меняется задним числом. Для новой попытки с запрещённым значением возвращается GENERATION_OPTION_NOT_AVAILABLE до ML.

Миграция V4 параметров из dev сохранена без изменений; ещё не влитые миграции BE-60 с разрешения пользователя перенумерованы в V6/V7. Проверки выполняются на новой БД. БД со старыми V4/V5 из прежней экспериментальной ветки не подключать к новой версии; ручной repair или удаление пользовательских volumes не выполнялись.

Полная локальная команда `clean test bootJar` на одноразовой PostgreSQL: 106 тестов прошли, один opt-in live-тест пропущен. Это не зелёный CI опубликованного SHA.

Последний совместный прогон после dev 8c94b25: полная локальная сборка на новой PostgreSQL — 106 тестов прошли (один live-тест пропущен). Отдельный настоящий вызов Super VL по TXT сохранил пять вопросов и завершился COMPLETED; изменение SQL-справочника отразилось в API, новое запрещённое значение отклонено, принятый снимок/идемпотентный повтор не изменились. Протокол — backend/ml-examples/combined-catalog-success-2026-11-03.json. CI и человеческое ревью новой ревизии пока не подтверждены; ограничения качества hard остаются.
