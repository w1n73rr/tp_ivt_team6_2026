Команды (корень репозитория, JDK 25 / Docker Desktop / Python 3):

```powershell
powershell -File backend/scripts/check-quiz-crud.ps1
python backend/scripts/check-attempts.py
node --test .github/scripts/changes.test.mjs tests/checks/generation-check.test.mjs
docker compose --env-file deploy/env/ci.env.example config --quiet
```

Первый скрипт поднимает отдельный PostgreSQL 16, запускает build и убирает свой
контейнер. Второй выполняет настоящий `docker compose up --build -d` отдельного
проекта (PostgreSQL + SeaweedFS + проверяемый app.jar) и проверяет настоящий HTTP/JWT:
запуск → PUT/повтор/замена/очистка → отказ → complete/повтор → result → новая
попытка → стабильный старый итог. Тесты генерации используют управляемый провайдер;
проверка попыток — заранее подготовленный исходный тест. Платная/внешняя LLM
не вызывается. Тестовые пароли и ключи одноразовые, реальные секреты не нужны.
Оба скрипта удаляют только собственные временные ресурсы.

Подробный JUnit HTML: `backend/build/reports/tests/test/index.html`, XML:
`backend/build/test-results/test/TEST-*.xml` (локальные артефакты, не коммитятся).
В CI те же тесты выполняются с отдельным PostgreSQL и TEST_DATABASE_* по TESTING.md.
