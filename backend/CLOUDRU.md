# Cloud.ru Foundation Models для генерации теста

Основное описание модуля, схема, промпт и JSON — [ML.md](ML.md). Эта страница дополняет его настройкой Cloud.ru.

Ветка `feature/tpivt6_26-64-cloudru` перенесена на актуальный dev Сферы `c009a53`.
Контракт `QuizGenerator.generate`, M1 v2, этапы и ошибки использует существующий backend.
Провайдер выбирается явно. Автоматического переключения между провайдерами нет.

## Выбор модели

Первый кандидат — `deepseek-ai/DeepSeek-V4-Flash`. Cloud.ru указывает поддержку
structured output и reasoning, размещение внешнее. Для внутреннего размещения
можно отдельно сравнить `deepseek-ai/DeepSeek-V4-Pro` или `openai/gpt-oss-120b`.
Качество выбранной модели подтверждается реальными результатами, а не описанием каталога.

По присланным пользователем ценам Flash 43,30 ₽ за миллион входных и 86,58 ₽
за миллион выходных токенов. 10 000 входных + 4 000 выходных стоят около 0,78 ₽.
Это оценка одного обращения. Проверка содержания и исправления оплачиваются отдельно.
Обычный generate делает два обращения, с исправлениями — до шести.
Reasoning также может увеличить тарифицируемый выход. Актуальную цену смотрите в кабинете.

## Ключ

Cloud.ru → Пользователи → Сервисные аккаунты → Создать аккаунт уровня Проект.
В аккаунте откройте Учётные данные доступа → Создать API-ключ,
выберите сервис Foundation Models и сохраните Key Secret.

Ключ задаётся только на сервере. Для локальной проверки сохраните его в
игнорируемом `.env.cloudru.local`. Compose читает корневой `.env` либо явно
переданный `--env-file`. Не коммитьте и не пересылайте env-файлы целиком.

```dotenv
ML_PROVIDER=cloudru
CLOUDRU_API_KEY=<Key Secret>
CLOUDRU_MODEL=deepseek-ai/DeepSeek-V4-Flash
CLOUDRU_TIMEOUT_SECONDS=90
CLOUDRU_MAX_OUTPUT_TOKENS=12000
```

Для обычного запуска внесите эти значения в локальный `.env`, сохранив остальные
секреты и параметры проекта, затем выполните `docker compose up -d --build`.
При обновлении работающего стенда применяйте штатную инструкцию релиза.

## Песочница

Экспорт использует настоящий сборщик промпта и учебную русскую лекцию из тестов.
Он сохраняет system и user отдельно для трёх типов, 5 вопросов, medium.

```powershell
$env:ML_EXPORT_SANDBOX='true'
.\backend\gradlew.bat -p backend test --tests '*CloudRuSandboxTest' --rerun-tasks
Remove-Item Env:ML_EXPORT_SANDBOX
```

Файлы находятся в `backend/build/cloudru-sandbox/`.
В песочнице выбранной модели вставьте `*-system.txt` в системную инструкцию,
`*-user.json` в пользовательское сообщение. Temperature 0.2, max_tokens 4000.
Начинайте новый диалог для каждого сценария. Сохраните полный ответ и расход токенов.
Песочница показывает ответ модели. Проверку JSON, review и запись в БД проверяем через модуль/API.

## Реальный прогон модуля

Перед запуском загрузите CLOUDRU_API_KEY из локального env-файла в окружение процесса.
Не вводите секрет в командную строку или чат.

```powershell
$env:ML_PROVIDER='cloudru'
$env:CLOUDRU_MODEL='deepseek-ai/DeepSeek-V4-Flash'
$env:ML_LIVE_TEST='true'
$env:ML_LIVE_TYPE='single_choice'
$env:ML_LIVE_COUNT='5'
$env:ML_LIVE_DIFFICULTY='medium'
.\backend\gradlew.bat -p backend test --tests '*OpenRouterLiveTest' --rerun-tasks
```

Имя существующего live-теста сохранено для совместимости команд.
В режиме cloudru он вызывает CloudRuClient с лимитом CLOUDRU_MAX_OUTPUT_TOKENS (по умолчанию 8000) выходных токенов
на обращение и расчётным бюджетом ML_LIVE_BUDGET_RUB=10 на весь процесс теста.
Оценка консервативна: один входной токен на байт UTF-8 плюс весь лимит выхода,
по приведённому тарифу Flash. При изменении тарифа обновите расчёт перед запуском.
Остановка по бюджету даёт CANCELLED/LIVE_BUDGET_LIMIT. Это ограничение ручного теста.
Лимит расходов в рублях настройте у провайдера, тест не знает фактический тариф.
Результаты и этапы сохраняются локально в `backend/build/ml-live/`.
Повторите для multiple_choice и true_false после оценки первого результата.
Проверьте ответы по лекции, уровень сложности, отсутствие смысловых дублей и подсказок длиной.

## DEV и сервер

Environment DEV в GitHub содержит Variables `ML_PROVIDER=cloudru`, `CLOUDRU_MODEL`
и Secret `CLOUDRU_API_KEY`. Ручной workflow «Реальная генерация DEV» передаёт ключ
только при старте backend. Обычный CI использует управляемый стенд.
На ВМ задайте те же значения в серверном окружении и пересоздайте backend
по инструкции выкладки. Проверьте HTTPS-доступность API с ВМ и настоящий путь
материал → задача → COMPLETED → один сохранённый тест после повторного чтения.

## Документация провайдера

- https://cloud.ru/docs/foundation-models/ug/topics/api-ref__specs
- https://cloud.ru/docs/foundation-models/ug/topics/overview__available__models

Клиент использует Bearer Key Secret, фиксированный HTTPS endpoint
`https://foundation-models.api.cloud.ru/v1/chat/completions`, streaming и JSON mode.
OpenRouter-поля provider/reasoning в Cloud.ru не отправляются. Настройку reasoning
для Cloud.ru оставляем провайдеру до проверки его параметров на реальном запросе.
Сохраняются общий deadline, лимиты SSE, проверка завершения, безопасные ошибки
и запрет перенаправлений с ключом.

В безопасной диагностике приложения отказ отмечается `PROVIDER_HTTP_402`,
машиночитаемый код задачи — MODEL_UNAVAILABLE. Перед повтором пополните баланс
нужного проекта Foundation Models или уточните подключение биллинга в Cloud.ru.
