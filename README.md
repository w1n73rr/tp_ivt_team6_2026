## Настройка генерации теста — прототип TY5 / 62

Дополнение: можно задать название теста (1–100 символов после обрезки пробелов).
Название сохраняется вместе с черновиком в памяти вкладки. На ожидании доступны явные
кнопки «Демо: тест готов» / «Демо: ошибка» для просмотра макетов конечных состояний.
Это локальная демонстрация без сохранения теста; название ещё не передаётся backend.

Из «Моих материалов» нажмите «Создать тест» у конкретного документа. Страница
`/materials/:materialId/generate` получает этот материал из существующего API.
Параметры генерации и запуск пока демонстрационные: серверная задача не создаётся,
тест не сохраняется. Экран явно сообщает об этом. Карточка не завершена до интеграции.

### Начальная настройка и запуск

Нужны Git и работающий Docker Desktop с Linux-контейнерами и Docker Compose.
Скопируйте репозиторий, перейдите в его корень. Для первоначальной сборки в **новой
копии с новой БД** выполните `docker compose up --build`. После сборки обычный запуск —
`docker compose up`. Дождитесь запуска сервисов, откройте `http://localhost:3000`.
Порты 3000, 8080, 5432 и 8333 должны быть свободны; при конфликте используйте
согласованную конфигурацию своего стенда. Не запускайте первоначальную настройку
поверх старой БД: backend применяет Flyway при старте. Существующие volumes не удаляйте.
Образы скачиваются из сети; локальные значения Compose предназначены для разработки.
Новых переменных окружения эта задача не добавляет, `.env` для неё не требуется.

Зарегистрируйте отдельного тестового пользователя либо войдите под своей учётной
записью. В «Моих материалах» загрузите небольшой TXT/PDF/DOCX, если список пуст.
Нужен работающий API материалов: при его ошибке настройки не подменяют документ примером.

### Приёмка прототипа

1. Нажмите «Создать тест» у материала. Проверьте название, формат и размер именно
   этого документа. Поля смены материала и отдельного пункта генерации в меню нет.
2. Переключите 5/10 вопросов и все три сложности. Сводка должна меняться.
   Выберите каждый тип по отдельности: всегда выбран ровно один.
3. Нажмите «Создать тест» дважды подряд. Во время отправки кнопка и параметры
   заблокированы. Откроется демонстрация ожидания без процентов, кнопки «К настройкам»,
   автоматического успеха и записи на сервер.
4. Вернитесь браузерной кнопкой к списку и откройте тот же материал: выбранные параметры
   сохранены в памяти вкладки. Для другого материала — свои параметры. После обновления
   страницы используются значения по умолчанию: 10, средняя, несколько ответов.
5. Откройте URL с несуществующим ID: видны ошибка, повтор и возврат к материалам,
   а не подставной документ. Проверьте экран на узком окне и управление с клавиатуры.

Локальные проверки (нужен Node.js, зависимости устанавливаются `npm --prefix frontend ci`):
`npm --prefix frontend run test -- --watch=false` и `npm --prefix frontend run build`.
Сборка загружает шрифт Google и требует доступа к сети. Локальные проверки не являются CI.
Чистый Compose-запуск другим участником и независимое ревью ещё требуют подтверждения.

Дополнительная проверка: задайте название теста, проверьте пустое значение и название
из пробелов — запуск должен быть отклонён. На демонстрационном ожидании по очереди
выберите «Демо: ошибка» и «Демо: тест готов». Возврат к настройкам сохраняет название
и параметры. Это черновые состояния до согласования макетов Figma.

На 30.10.2026 локально прошли 63 теста и production-сборка. Проверочный Docker-стенд
обновлён упаковкой этой сборки в Nginx. Полная сборка стандартным Dockerfile завершилась
сетевой ошибкой загрузки Google Fonts; воспроизводимость чистого Compose-запуска пока
не подтверждена. Работающий стенд сам по себе не доказывает выполнение этого пункта DoD.

### Подключение backend

`GENERATION_SOURCE` отделяет демонстрационные параметры/запуск от экрана. После согласования
FE/BE замените провайдер на HTTP-адаптер, расширьте результат запуска идентификатором реальной
задачи и подключите согласованный API статуса и отдельные конечные формы. Нельзя просто
снять пометку деморежима: реального опроса и серверного сохранения здесь ещё нет.
`GenerationSettings` — модель UI, а не утверждённый HTTP-контракт: PDF предлагает `/api/tests`,
репозиторий описывает `/api/quizzes`; формат единственного типа нужно согласовать.
Страницы успеха/ошибки и таблица тестов — следующие задачи. Темы, персонализация,
несколько материалов и прохождение исключены из текущего объёма.

# Автотесты TY3 Backend

Проект автотестов REST API с использованием **Spring Boot Test** и **REST Assured**.

## Структура проекта автотестов
`src/test/java/tech/genna/TY3/`
- `config/` — конфигурация REST Assured и базовых спецификаций запросов/ответов.
- `client/` — HTTP-клиенты для взаимодействия с API эндпоинтами.
- `tests/base/` — базовые тестовые классы с логикой поднятия контекста Spring Boot.
- `tests/auth/` — автоматизированные тесты аутентификации и авторизации.
