  списка оставляют ожидание. Готовность требует COMPLETED, quizId и найденную запись

- Таблица читает только собственные серверные тесты. Переход результата выделяет строку.
- Переименование/удаление отключены, поскольку соответствующего API нет. Моки не применяются

## Исправления авторизации и устойчивости ML после ручной проверки

Всё в той же feature-ветке, origin/dev не изменён. В nginx два 401 по задаче
9cbd8609-eab7-44e8-abe0-38f843e2c5fb пришли после её завершения без Referer.
Это согласуется с ручным открытием API, но само по себе не доказывает источник запроса.
Контрольный настоящий сценарий: регистрация отдельного пользователя, чтение собственного
списка и параметров с Bearer — 200; без Bearer — 401 AUTHENTICATION_REQUIRED.
Отсутствие авторизации не было причиной сохранённого INVALID_MODEL_OUTPUT.

Frontend теперь различает 401 и временную сетевую ошибку: прекращает HTTP-опрос,
предлагает вход и безопасный возврат к UUID-маршруту того же материала; принятый job
и ключ остаются в sessionStorage. Внешние адреса возврата по-прежнему запрещены.

ML-клиент теперь запрашивает response_format=json_object и provider.require_parameters=true:
провайдер должен поддерживать JSON-режим вместо молчаливого игнорирования параметра.
Поддержка response_format/structured_outputs проверена по публичным metadata endpoint
выбранной модели 03.11.2026. Это обеспечивает выбор режима, но не доказывает правильность
содержания. Все строгие проверки количества, ключей ответа и качества сохранены.
Источник: https://openrouter.ai/api/v1/models/nvidia/nemotron-3.5-super-vl:free/endpoints
Описание JSON-режима: https://github.com/OpenRouterTeam/docs/blob/main/api_reference/overview.mdx

ответ модели, токены и provider key не логируются. Для старой задачи точное нарушение
