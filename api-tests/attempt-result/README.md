# API получения результата и ответов

`AttemptResultApiTest` находится в `api-tests`, написан на Java/JUnit 5 и обращается к HTTP API через Rest Assured. Три независимых сценария проверяют SINGLE_CHOICE (5), TRUE_FALSE (10), MULTIPLE_CHOICE (5). Каждый регистрирует двух синтетических пользователей, загружает лекцию, создаёт тест, сохраняет ответы и завершает попытку через API.

Реальные компоненты — backend проверяемой ветки, PostgreSQL, SeaweedFS, сохранение попыток и расчёт результата. Внешняя модель заменена существующим `GenerationUiTestServer`: ответы воспроизводимы, OpenRouter и Cloud.ru не вызываются. Контрольный ответ определяется фиксированной тестовой моделью, а не ответом публичного API. Другие тесты с переключением режима ML одновременно на этом стенде не запускайте.

## Подготовка один раз

Нужны работающий Docker Desktop с Linux-контейнерами, Docker Compose и JDK 17+ для запуска Java-тестов на Windows. Выполняйте из корня репозитория. Создайте отдельный `.env.result-api.local`, если его ещё нет, и заполните POSTGRES_PASSWORD, JWT_SECRET, S3_ACCESS_KEY, S3_SECRET_KEY независимыми случайными значениями по корневому README. Подойдёт копия `.env.example`. Внешние ключи модели оставьте пустыми. Этот файл игнорируется Git. Используются существующие переменные окружения, новые секреты в примеры не добавляются.

```powershell
Copy-Item .env.example .env.result-api.local
notepad .env.result-api.local
```

Команду копирования выполняйте только при отсутствии файла. База стенда изолирована и хранится в tmpfs. Старые пользовательские БД не подключаются. Порт 18085 должен быть свободен. Пример инициализации и запуска:

```powershell
docker compose --env-file .env.result-api.local -f api-tests/attempt-result/compose.yml up -d --build --wait
```

Первая подготовка скачивает Java/Gradle и зависимости, компилирует backend и может занять несколько минут. Оставьте стенд запущенным для повторных прогонов. Зависимости Gradle сохраняются в отдельном томе. После изменения кода backend повторите подготовку со сборкой. Для запуска ранее собранного стенда используйте ту же команду без `--build`.

## Повторный запуск тестов без сборки Docker

```powershell
Set-Location "$env:USERPROFILE\Projects\tp_ivt_team6_2026"
$env:API_BASE_URL = 'http://localhost:18085'
$env:API_TEST_DISPOSABLE = 'true'
$env:API_TEST_VERSION = (git rev-parse HEAD)
.\tests\ui\gradlew.bat -p .\api-tests test -PattemptResult
Invoke-Item .\api-tests\build\reports\tests\test\index.html
```

В новом окне PowerShell при необходимости задайте JAVA_HOME на установленный JDK. Папка `tests/ui` в команде содержит общий Gradle wrapper; запускаемый модуль — `api-tests`. В IDE импортируйте Gradle-модуль `api-tests`, укажите те же три переменные и запускайте класс `AttemptResultApiTest` кнопкой рядом с классом. Тег выбран автоматически при прямом запуске JUnit из IDE. Для Gradle запуска укажите `-PattemptResult`.

HTML содержит результаты утверждений. `api-tests/build/reports/attempt-result-http.json` содержит версию, окружение, ожидаемые/фактические HTTP-коды каждого сценария. Авторизация и пароли в отчёт не записываются. Повторный прогон заменяет отчёты предыдущего. Регистрации и материалы остаются в отдельной временной БД до остановки.

## Покрытие

- GET `/api/attempts/{id}/result` — 200 для завершённой собственной попытки. Вопросы, порядок, варианты, выбранные и правильные ответы, оценка каждого вопроса, счётчики, процент, дата и длительность сопоставляются с сохранёнными ответами и завершением.
- Пропущенный вопрос считается отдельно и получает 0, полный правильный ответ получает 1, ошибочный получает 0. Проверяются 60% для SINGLE_CHOICE, 80% для TRUE_FALSE и 40% для MULTIPLE_CHOICE. Для MULTIPLE_CHOICE дополнительно проверен неполный правильный набор: по текущему OpenAPI он получает 0. Повтор с пустыми ответами даёт 0 и все вопросы пропущены.
- Своя активная попытка — 409 RESULT_NOT_READY, её состояние остаётся IN_PROGRESS. Публичное чтение до и после сохранения ответов не содержит ключей и оценки.
- Без JWT — 401 AUTHENTICATION_REQUIRED. Чужой и отсутствующий UUID — одинаковый ответ 404 ATTEMPT_NOT_FOUND. Отказы ограничены полями code/message и необязательным пустым fieldErrors.
- `/review` — 404 и отсутствие вопросов и ответов.
- Новая попытка имеет новый ID и пустые ответы. Повторное чтение исходного результата до и после завершения повтора побайтно по JSON-значениям подтверждает неизменность снимка. Успешный `/result` имеет Cache-Control: no-store.

## Расхождение приложенных кейсов и контракта

OpenAPI версии dev 7c19309 задаёт целочисленный score вопроса 0/1 и scorePercent = 100 * correctCount / totalQuestions с двумя знаками. Приложенные UI-кейсы предполагают частичные баллы C/K и другой расчёт процента. В этом наборе используется опубликованный OpenAPI. Расхождение требует согласования аналитика/PO и backend до приёмки частичного оценивания. Значения длительности 765/3600 секунд и формат времени UI здесь не проверяются; проверяется сохранённая серверная длительность. Сбои сохранения/сети и внешний ML находятся за пределами этого набора получения результата.
