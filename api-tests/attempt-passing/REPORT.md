## Версия и окружение

Windows 10, Docker Desktop (Linux), JDK 17 / Gradle 8.5 на стороне проверок, backend Java 25.0.5, PostgreSQL 16.15 и SeaweedFS 4.48. Реальный HTTP API доступен на http://localhost:18085, Compose-проект attempt-result-api, временная изолированная БД generation_ui_controlled. Использован уже запущенный стенд предыдущей задачи.

Стенд собран на исходниках backend коммита 7c19309. Подкаталог backend этой версии и актуальной базы 621eee1 побайтово совпадает по Git tree 4375ff033414f273c29107c99e95e372706a7f9e. Отличия dev после сборки относятся к другим каталогам. Указанная проверяемая база соответствует реально запущенному коду backend, его перестройка не требовалась.

При подготовке создаются пользователи, материалы и тесты через HTTP API. Внешняя модель заменена существующим GenerationUiTestServer с фиксированными ответами. Во время старта, чтения, записи и завершения выполняются продуктовые контроллеры/сервисы и реальные транзакции PostgreSQL. Внешний ML и UI не проверяются.

## Повторение и границы

Инструкция, сервисы, настройки окружения и пример входных данных — README.md в этом каталоге. Корневой README содержит ссылку. Для повторного прогона достаточно работающего стенда и Gradle-команды, сборка Docker на каждый тест не выполняется. Новых переменных окружения нет; реальные пароли/ключи живут в игнорируемом .env.result-api.local.

Подготовительные запросы генерации видны в журнале до запросов прохождения. Новый старт использует существующий quizId и публичные вопросы. Тестовый клиент не вызывает повторную генерацию при прохождении. Счётчик реальных вызовов модели отдельно не измерялся.

Приложенные кейсы включают UI и предварительные вопросы к PO. Проверены API-части по текущему OpenAPI: пустой массив разрешён, одна активная попытка, повтор после complete разрешён, чужой/несвязанный вопрос — 404. Частичные баллы не предусмотрены. Навигация UI, отображение ошибок, несохранённый локальный выбор и отмена диалога относятся к UI-приёмке. Принудительный отказ БД/сети не воспроизводился; повтор операций и стабильность сохранённого итога проверены реальными HTTP-запросами.

По выполненным HTTP-проверкам дефектов не обнаружено, новых задач о дефектах не создано. Правила, которые в приложенных кейсах отмечены как предварительные, сверены с опубликованным серверным контрактом. Чистое развёртывание на другом компьютере остаётся отдельной проверкой участника команды.
